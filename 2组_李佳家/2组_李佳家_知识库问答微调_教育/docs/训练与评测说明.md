# 训练与评测说明

## 1. 实验环境

| 项目 | 配置 |
| --- | --- |
| 操作系统 | Windows 11 |
| Python | 3.12.8 |
| PyTorch | 2.12.1（CPU） |
| Transformers | 5.2.0 |
| PEFT | 0.20.0 |
| 处理器 | 6 核 CPU（无独立 GPU） |
| 基座模型 | Qwen2.5-0.5B-Instruct（本机 ModelScope 缓存，502.8M 参数） |

> 由于实验机没有可用的 NVIDIA GPU，训练与推理全部在 CPU 上完成。脚本同时兼容 CUDA：`--device cuda` 时会自动使用 bf16。

## 2. 训练配置

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| LoRA rank / alpha | 16 / 32 | 缩放系数 alpha/r = 2 |
| LoRA dropout | 0.05 | |
| 目标模块 | q/k/v/o/gate/up/down_proj | 7 个投影层 |
| 可训练参数 | 8,798,208 / 502,830,976 | 占 1.75% |
| 最大序列长度 | 576 | 训练集最长 533 tokens，无截断 |
| batch size | 1 | 每条样本约 300-530 tokens |
| 梯度累积 | 2 | 等效 batch = 2 |
| 学习率 | 2.5e-4 | AdamW，余弦退火，warmup 5 步 |
| 训练步数 | 60 | 约 120 条样本、0.29 个 epoch |
| 验证集 | 60 条 | 每 20 步评估一次 |
| 精度 | fp32 | CPU 无 bf16 |
| 训练耗时 | 13.2 分钟 | 平均约 13 秒/步，约 70 tokens/s |

损失计算只针对 assistant 回复：system 与 user 部分的 label 置为 `-100`，避免模型学习复述提示词。

## 3. 训练过程

| 步数 | 训练损失 | 验证损失 | 说明 |
| --- | --- | --- | --- |
| 1 | 1.68 | - | warmup 阶段 |
| 5 | 1.21 | - | 学习率升至 2.5e-4 |
| 20 | 0.59 | 0.4048 | 开始学习“结论 / 要点 / 依据”格式 |
| 40 | 0.43 | 0.2681 | 引用编号与拒答话术基本稳定 |
| 60 | 0.19 | 0.2501 | 余弦退火至 0，保存最优适配器 |

训练损失在第 40 步后进入 0.2 左右并伴随波动（小批量 + 模板化数据），验证损失持续下降，未出现过拟合拐点。完整逐步日志见 `outputs/training_log.csv`，控制台日志见 `outputs/train_console.log`。

## 4. 评测设置

- 测试集：`data/test.jsonl` 中每个能力维度固定取 5 条，共 25 条，训练与验证均未使用；拒答维度固定取 2 条“资料冲突”+ 3 条“资料不足”；
- 提示词：与训练一致的 system + 检索片段 + 问题，不额外加 few-shot；
- 解码：贪心解码（temperature=0），`max_new_tokens=180`；
- 基线：原始 Qwen2.5-0.5B-Instruct；
- 微调：同一基座 + `outputs/lora_adapter`；
- 指标全部由 `scripts/evaluate.py` 规则化计算，可复算。

### 指标定义

| 指标 | 定义 | 适用 |
| --- | --- | --- |
| 引用 F1 | 引用编号必须在资料中出现（精确率），且覆盖标准依据条款（召回率），两者调和平均 | 可回答样本 |
| 要点覆盖率 | 标准要点与生成答案的字符 3-gram 重合比例 ≥ 0.35 视为覆盖 | 可回答样本 |
| 数字忠实度 | 答案中出现的时间/金额/百分比能否在资料中找到；无数字记 1.0 | 可回答样本 |
| 格式合规率 | 是否包含“结论/要点/依据/步骤”等规定结构 | 全部样本 |
| 术语准确率 | 条款标注的行业术语在答案中的命中比例 | 可回答样本 |
| 拒答正确率 | 资料不足时拒答、可回答时不误拒答 | 全部样本 |
| 综合得分 | 可回答样本按 引用 0.25 + 覆盖 0.25 + 数字 0.20 + 格式 0.15 + 术语 0.15 加权；拒答样本按 拒答 0.7 + 格式 0.3 | 全部样本 |

> 拒答维度不使用引用、覆盖、数字、术语指标，总体汇总也只对可回答样本求这几项平均，避免“不适用”被当成 0 分。

## 5. 评测结果

### 5.1 总体指标

| 指标 | 基线模型 | 微调模型 | 变化 |
| --- | --- | --- | --- |
| 引用 F1 | 0.100 | **0.950** | +0.850 |
| 要点覆盖率 | 0.774 | 0.888 | +0.114 |
| 数字忠实度 | 0.980 | **1.000** | +0.020 |
| 格式合规率 | 0.040 | **0.880** | +0.840 |
| 术语准确率 | 0.825 | 0.808 | -0.017 |
| 拒答正确率 | 0.880 | 0.920 | +0.040 |
| **综合得分** | **0.527** | **0.859** | **+0.332** |

### 5.2 分能力维度

| 能力维度 | 基线综合 | 微调综合 | 提升 |
| --- | --- | --- | --- |
| 行业术语与格式适配 | 0.633 | 0.968 | +0.335 |
| 检索内容忠实回答 | 0.474 | 0.980 | +0.506 |
| 多片段信息整合 | 0.445 | 0.805 | +0.360 |
| 证据引用与出处标注 | 0.601 | 0.941 | +0.340 |
| 资料不足拒答 | 0.480 | 0.600 | +0.120 |

### 5.3 结果分析

1. **格式与引用是提升最大的部分**：基座模型习惯用“根据资料……”的自然段回答，只有 4% 的答案带规定结构、引用 F1 仅 0.10；微调后 88% 的答案包含“结论 / 要点 / 依据”，引用 F1 达到 0.950。
2. **忠实性与完整性同步改善**：数字忠实度从 0.98 提升到 1.00，要点覆盖率从 0.774 提升到 0.888；在带干扰条款的样本上，微调模型没有再抄错干扰数字。
3. **多片段整合明显进步**：从 0.445 提升到 0.805，4/5 的多条款问题能同时引用两条依据；仍有 1 条退化为单条款回答，是后续补数据的重点。
4. **拒答维度暴露真实短板**：5 条应拒答样本中，3 条“资料不足”全部正确拒答，但 2 条“新旧版本冲突”样本误用了历史版本中的数字（30 个工作日、30 天回放），导致该维度只有 0.600。这说明模型学会了“没有资料就拒答”，但还不能稳定识别“资料互相矛盾”。
5. **术语准确率基本持平（0.825 → 0.808）**：模型学会压缩回答，个别术语被同义表述替代，但整体口径未跑偏。

## 6. 复现与调参建议

```bash
# 完整复现（CPU 约 15 分钟）
python scripts/generate_dataset.py
python scripts/check_dataset.py
python scripts/train_lora.py --max_steps 60 --max_length 576 --grad_accum 2 --lr 2.5e-4
python scripts/evaluate.py --tag base --limit 5
python scripts/evaluate.py --tag tuned --adapter outputs/lora_adapter --limit 5
python scripts/export_details.py
python scripts/make_report.py
```

- **有 GPU 时**：`--device cuda --batch_size 8 --grad_accum 2 --max_steps 300 --max_length 1024`，约 3 个 epoch，通常可以把多片段整合和术语指标同时拉高；
- **换更大模型**：同一份数据可直接用于 Qwen2.5-7B-Instruct 的 LoRA（修改 `--model_path` 与 `--lora_r 32`）；
- **扩充数据**：优先补充“多条款组合 + 干扰条款”样本和真实客服问法，减少模板痕迹。

## 7. 局限

- 训练步数受 CPU 限制，仅 0.29 个 epoch，模型更多是在学习输出规范，而非深度理解业务；
- 评测集与训练集同源（同一知识库、同一套模板），分数偏高，不能直接等同于线上效果；
- 规则指标无法评价语言流畅度和隐含语义，建议补充人工抽检；
- 0.5B 模型在长上下文和复杂多跳问题上能力有限，生产环境建议更大基座 + 更充分训练。
