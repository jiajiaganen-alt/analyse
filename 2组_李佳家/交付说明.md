## 二、项目一：电商风险控制系统（Agent）

**位置**：`3组_张晨_电商风控_电商`

- 风险 Agent：确定性六步编排（事件校验 → 特征计算 → 规则匹配 → 评分决策 → 黑名单校验 → 案件生成），每一步耗时、状态、摘要作为 trace 返回并落库；
- 业务规模：39 项风险特征、30 条可启停规则、24 个 OpenAPI 接口；
- 主演示链路：用户 `U1001` 发起售后申请 → 100.0 分 / 高风险 / 拒绝 / 命中 10 条规则与 2 条黑名单 / 自动创建案件 `CASE-000013` → 人工审核 → 审核日志留痕；
- 页面：风险检查、规则管理、案件管理（详情抽屉 + 审核）、黑名单、用户画像、运营看板、离线接口文档；
- 验证：`python -m pytest -q` → **24 passed**；`tests/smoke_test.py` 18 次接口调用全部 200。

**启动**：

```powershell

# 浏览器打开 http://127.0.0.1:8713 ，首次启动自动建库并灌演示数据
```

## 三、项目二：舆情分析平台（Agent）

**位置**：`3组_张晨_舆情分析_舆情`

- Agent 流水线：多来源检索 → 观点/情绪/风险抽取 → 洞察汇总 → 报告生成 → 图谱构建，完整耗时约 600ms；

- 页面：控制台、主题检索（含时间线、渠道、情绪、证据、来源清单）、论坛监控、图谱查看器（力导向/分层、节点详情与来源引用）、配置管理、系统状态、接口文档；

- 验证：`python -m pytest -q` → **27 passed**；18 个核心接口、WS、`/graph-viewer/{report_id}`、`/docs` 均实测通过。

## 四、项目三：知识库问答模型微调（Fine-tune）

**位置**：`3组_张晨_知识库问答微调_教育`

- 任务：在线教育知识库的检索增强问答，要求依据资料作答、标注条款引用、资料不足时拒答；
- 数据：6 篇制度文档 / 37 个条款 → 560 条指令样本（420 训练 / 60 验证 / 80 测试），覆盖 5 个能力维度；
- 训练：Qwen2.5-0.5B-Instruct + LoRA（r=16，可训练参数 8.80M，占 1.75%），CPU 训练 60 步、约 13 分钟，验证损失 0.4048（20 步）→ 0.2501（60 步）；
- 评测：25 条留出样本，基线与微调同题对比，综合得分 **0.527 → 0.859（+0.332）**；引用 F1 0.100 → 0.950，格式合规率 0.040 → 0.880，多片段整合 0.445 → 0.805；资料冲突型拒答仍是短板（0/2）；
- 交付物：LoRA 适配器（约 35MB）、训练日志、逐条评测 JSON/CSV、5 页离线实验报告（`report/index.html`）、5 张报告截图。

**复现**：

```powershell
cd "3组_张晨_知识库问答微调_教育"
python scripts/generate_dataset.py
python scripts/check_dataset.py
python scripts/train_lora.py --max_steps 60 --max_length 576 --grad_accum 2 --lr 2.5e-4
python scripts/evaluate.py --tag base --limit 5
python scripts/evaluate.py --tag tuned --adapter outputs/lora_adapter --limit 5
python scripts/make_report.py
```

> 训练脚本默认读取本机模型缓存 `D:\ai_models\modelscope_cache\models\Qwen\Qwen2___5-0___5B-Instruct`，可通过 `--model_path` 指定其他本地 Qwen2.5 模型。

**测试截图**（5 张）：实验总览、数据集构建、训练过程与损失曲线、评测指标对比、样例对比（基线 vs 微调）。

## 六、说明

1. 三个项目均完全离线运行，不调用外部大模型 API，不依赖 CDN、外部字体或外部图片；
2. 为保证包体精简，未包含 `.venv`、`node_modules`、`__pycache__`、数据库文件和 PyPI 依赖；两个 Agent 项目首次启动会自动初始化演示数据，微调项目提供数据生成脚本与已生成数据；
3. 微调项目不包含基座模型权重，只包含 LoRA 适配器；基座模型需按 README 中的路径准备；
4. 文件夹命名规则为「组名_姓名_项目_行业」，如组名或行业需要调整，直接重命名文件夹即可，不影响运行；
5. 各项目的截图均为真实浏览器渲染结果，可用项目内 `截图脚本.ps1` 重新生成。
